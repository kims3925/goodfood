## 1. 인증 (Authentication)

사용자 인증 및 세션 관리 기능을 제공합니다.

### 기능 목록

| 기능ID | Depth1 | Depth2 | Depth3 | 기능설명 |
|--------|--------|--------|--------|----------|
| auth-1 | 로그인/회원가입 | 회원가입 | 사용자 등록 및 검증 | 이메일과 비밀번호를 입력받아 신규 사용자 계정을 생성합니다. |
| auth-2 | 로그인/회원가입 | 로그인 | 자격증명 확인 및 세션 생성 | 이메일과 비밀번호로 사용자 인증을 처리합니다. |
| auth-3 | 로그인/회원가입 | 로그아웃 | 세션 파기 및 쿠키 삭제 | 현재 로그인 세션을 종료하고 관련 데이터를 정리합니다. |
| auth-4 | 로그인/회원가입 | 세션 관리 | 세션 상태 확인 및 갱신 | 클라이언트에서 현재 로그인 상태와 사용자 정보를 조회하고 관리합니다. |

### 상세 설명

#### auth-1: 회원가입
- **목적**: 신규 사용자 계정 생성
- **프로세스**: 사용자 등록 및 검증
- **구현**: 이메일과 비밀번호를 입력받아 신규 사용자 계정을 생성합니다.

#### auth-2: 로그인
- **목적**: 사용자 인증 처리
- **프로세스**: 자격증명 확인 및 세션 생성
- **구현**: 이메일과 비밀번호로 사용자 인증을 처리합니다.

#### auth-3: 로그아웃
- **목적**: 로그인 세션 종료
- **프로세스**: 세션 파기 및 쿠키 삭제
- **구현**: 현재 로그인 세션을 종료하고 관련 데이터를 정리합니다.

#### auth-4: 세션 관리
- **목적**: 로그인 상태 관리
- **프로세스**: 세션 상태 확인 및 갱신
- **구현**: 클라이언트에서 현재 로그인 상태와 사용자 정보를 조회하고 관리합니다.

## 2. 밴드관리 (Band Management)

Band 플랫폼과의 연동을 통한 밴드 관리 및 게시물 발행 기능을 제공합니다.

### 기능 목록

| 기능ID | Depth1 | Depth2 | Depth3 | 기능설명 |
|--------|--------|--------|--------|----------|
| band-1 | 밴드 목록 조회 | Band API 연동 | 외부 API 호출 및 데이터 파싱 | Band API를 호출하여 사용자가 가입한 모든 밴드 목록을 가져옵니다. |
| band-2 | 밴드 생성 | 밴드 등록 | DB 저장 및 분류 | 조회된 밴드 정보를 도매 또는 소매 밴드로 분류하여 DB에 저장합니다. |
| band-3 | 밴드 삭제 | 밴드 등록 해제 | Soft Delete 처리 | 등록된 밴드를 삭제하고 관련 데이터를 처리합니다 (Cascade). |
| band-4 | 밴드 게시물 발행 | 소매밴드 포스팅 | Band API 포스팅 실행 | 가공된 게시물을 선택된 소매밴드에 자동으로 발행합니다. |

### 상세 설명

#### band-1: 밴드 목록 조회
- **목적**: 사용자 가입 밴드 목록 조회
- **프로세스**: Band API 연동 → 외부 API 호출 및 데이터 파싱
- **구현**: Band API를 호출하여 사용자가 가입한 모든 밴드 목록을 가져옵니다.

#### band-2: 밴드 생성 (등록)
- **목적**: 밴드 정보 시스템 등록
- **프로세스**: 밴드 등록 → DB 저장 및 분류
- **구현**: 조회된 밴드 정보를 도매 또는 소매 밴드로 분류하여 DB에 저장합니다.
- **특징**: 도매/소매 밴드 자동 분류

#### band-3: 밴드 삭제
- **목적**: 등록된 밴드 제거
- **프로세스**: 밴드 등록 해제 → Soft Delete 처리
- **구현**: 등록된 밴드를 삭제하고 관련 데이터를 처리합니다 (Cascade).
- **특징**: Soft Delete 방식 사용, Cascade 삭제

#### band-4: 밴드 게시물 발행
- **목적**: 소매밴드에 게시물 자동 발행
- **프로세스**: 소매밴드 포스팅 → Band API 포스팅 실행
- **구현**: 가공된 게시물을 선택된 소매밴드에 자동으로 발행합니다.

## 3. 소싱 (Sourcing)

도매밴드에서 게시물을 조회하고 관리하는 기능을 제공합니다.

### 기능 목록

| 기능ID | Depth1 | Depth2 | Depth3 | 기능설명 |
|--------|--------|--------|--------|----------|
| sourcing-1 | 관리자 밴드 게시물 조회 | 게시물 조회 | Band API 요청을 통한 게시물 조회 | 선택된 도매밴드에서 게시물 데이터를 API요청을 통해 조회합니다. |
| Sourcing-2 | 게시물 조회 | 목록 UI 표시 | 필터링 및 페이지네이션 | 조회된 게시물 목록을 조회하고 UI에 표시합니다. |
| sourcing-3 | 게시물 생성 | 게시물 생성 | 조회된 게시물 목록중 선택된 게시물들을 생성합니다. | 조회된 게시물을 선택하여 게시물로 생성합니다. |
| sourcing-4 | 게시물 삭제 | 게시물 제거 | Soft Delete 및 로깅 | 게시물을 삭제합니다. |
| sourcing-5 | 게시물 수정 | 내용 및 가격 수정 | 수동 편집 또는 AI 재가공 | 가공된 게시물의 내용, 가격정책, 이미지를 수정합니다. |

### 상세 설명

#### sourcing-1: 관리자 밴드 게시물 조회
- **목적**: 도매밴드 게시물 데이터 수집
- **프로세스**: 게시물 조회 → Band API 요청을 통한 게시물 조회
- **구현**: 선택된 도매밴드에서 게시물 데이터를 API요청을 통해 조회합니다.

#### sourcing-2: 게시물 목록 UI 표시
- **목적**: 조회된 게시물 시각화
- **프로세스**: 목록 UI 표시 → 필터링 및 페이지네이션
- **구현**: 조회된 게시물 목록을 조회하고 UI에 표시합니다.
- **특징**: 필터링 및 페이지네이션 지원

#### sourcing-3: 게시물 생성
- **목적**: 선택된 게시물 시스템 등록
- **프로세스**: 게시물 생성 → 선택된 게시물들 생성
- **구현**: 조회된 게시물을 선택하여 게시물로 생성합니다.

#### sourcing-4: 게시물 삭제
- **목적**: 불필요한 게시물 제거
- **프로세스**: 게시물 제거 → Soft Delete 및 로깅
- **구현**: 게시물을 삭제합니다.
- **특징**: Soft Delete 방식, 로깅 기능

#### sourcing-5: 게시물 수정
- **목적**: 게시물 내용 편집
- **프로세스**: 내용 및 가격 수정 → 수동 편집 또는 AI 재가공
- **구현**: 가공된 게시물의 내용, 가격정책, 이미지를 수정합니다.
- **특징**: 수동 편집 및 AI 재가공 지원

- **AI 엔진**: Gemini AI
- **추출 데이터**: 상품명, 가격, 카테고리

#### ai-2: AI 게시물 수정
- **목적**: 판매용 콘텐츠 자동 생성
- **프로세스**: 콘텐츠 자동 생성 → 제목/설명 가공 및 저장
- **구현**: AI 분석 결과를 기반으로 판매용 콘텐츠를 자동 생성합니다.
- **생성 콘텐츠**: 제목, 설명

## 5. 주문서 (Purchase Order)

주문서 생성 및 관리 기능을 제공합니다.

### 기능 목록

| 기능ID | Depth1 | Depth2 | Depth3 | 기능설명 |
|--------|--------|--------|--------|----------|
| po-1 | 주문서 생성 | 주문 데이터 입력 | 고객정보/상품/금액 입력 | 새로운 주문서를 생성하고 DB에 저장합니다. |
| po-2 | 주문서 조회 | 목록 및 상세 조회 | 필터링/검색/정렬 | 주문서 목록과 상세 정보를 조회합니다. |
| po-3 | 주문서 수정 | 상태/정보 변경 | 주문 확인/배송/완료 처리 | 주문서의 상태와 정보를 수정합니다. |
| po-4 | 주문서 삭제 | 취소 및 완전삭제 | 주문 취소 또는 데이터 제거 | 주문서를 취소하거나 완전 삭제합니다. |

### 상세 설명

#### po-1: 주문서 생성
- **목적**: 신규 주문 등록
- **프로세스**: 주문 데이터 입력 → 고객정보/상품/금액 입력
- **구현**: 새로운 주문서를 생성하고 DB에 저장합니다.
- **입력 데이터**: 고객정보, 상품, 금액

#### po-2: 주문서 조회
- **목적**: 주문 내역 확인
- **프로세스**: 목록 및 상세 조회 → 필터링/검색/정렬
- **구현**: 주문서 목록과 상세 정보를 조회합니다.
- **특징**: 필터링, 검색, 정렬 기능 지원

#### po-3: 주문서 수정
- **목적**: 주문 상태 관리
- **프로세스**: 상태/정보 변경 → 주문 확인/배송/완료 처리
- **구현**: 주문서의 상태와 정보를 수정합니다.
- **상태 관리**: 주문 확인, 배송, 완료

#### po-4: 주문서 삭제
- **목적**: 주문 취소 또는 제거
- **프로세스**: 취소 및 완전삭제 → 주문 취소 또는 데이터 제거
- **구현**: 주문서를 취소하거나 완전 삭제합니다.
- **삭제 방식**: 취소(Soft Delete) 또는 완전삭제(Hard Delete)

