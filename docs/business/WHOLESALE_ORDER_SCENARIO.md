# 도매처 정산(발주) 시나리오 정의서

## 1. 개요

### 1.1 비즈니스 모델

**위탁/드롭쉬핑 모델**
- 재고를 보유하지 않고, 주문 발생 시 도매처에 발주
- 도매처가 고객에게 직배송

### 1.2 핵심 흐름

```
고객 결제완료 → 도매처별 주문 집계 → 엑셀 추출 → 매니저 수동 발주 → 도매처 배송
```

### 1.3 전체 정산 흐름 구조

```
[도매처(도매밴드)] ──상품공급──▶ [쇼핑몰(ABC마켓)] ──상품발행──▶ [소매처(소매밴드)] ──판매──▶ [고객]
        ◀──원가정산(발주)──                    ◀──수수료정산──
```

---

## 2. 상세 프로세스

### 2.1 주문 수집 (자동)

1. 고객이 쇼핑몰에서 상품 구매 및 결제 완료
2. 결제 완료된 주문이 **발주 대기** 상태로 자동 진입
3. 주문 상품별로 원본 도매처(도매밴드) 정보 연결

### 2.2 도매처별 분류 및 집계

1. 결제 완료 주문을 도매처(도매밴드) 기준으로 분류
2. 하나의 주문에 여러 도매처 상품 포함 가능 → 상품 단위로 분리
3. 도매처별 발주 대기 건수/금액 집계

### 2.3 발주 대상 조회

1. 관리자가 도매처 정산(발주) 관리 화면에서 확인
2. 도매처별 카드 UI로 현황 표시
3. 상세 클릭 시 발주 대상 주문 목록 조회

### 2.4 엑셀 추출

1. **엑셀 다운로드** 버튼 클릭
2. 도매처가 발주 처리 가능한 형식으로 자동 생성
3. 추출 시 해당 건들 **발주 완료** 상태로 변경 (선택적)

### 2.5 도매처 발주 (수동)

1. 담당 매니저가 추출된 엑셀 파일을 도매처에 전달
   - 밴드 메시지
   - 카카오톡
   - 이메일 등
2. 시스템에 발주 완료 처리

## 3. 상태 관리

### 3.1 주문 상태 vs 발주 상태

| 구분 | 상태 흐름 | 관리 주체 |
|------|----------|----------|
| 주문 상태 | PENDING → PAID → SHIPPED → DELIVERED | 쇼핑몰-고객 |
| 발주 상태 | 발주대기 → 발주완료 → (배송중) | 쇼핑몰-도매처 |

### 3.2 발주 상태 정의

| 상태 | 코드 | 설명 |
|------|------|------|
| 발주대기 | `PENDING` | 결제 완료, 도매처 발주 전 |
| 발주완료 | `ORDERED` | 도매처에 발주 전달 완료 |
| 배송중 | `SHIPPING` | 도매처가 상품 발송 (선택) |
| 완료 | `COMPLETED` | 고객 수령 완료 |

---

## 4. 관리 화면 구성

### 4.1 도매처 목록 (카드형)

각 도매처 카드 표시 정보:

| 항목 | 설명 |
|------|------|
| 도매처명 | 도매밴드명 |
| 발주대기 건수 | 발주 필요한 주문 수 |
| 발주대기 금액 | 도매원가 기준 합계 |
| 최근 발주일 | 마지막 발주 처리일 |

### 4.2 도매처 상세 화면

**발주 대기 목록**

| 주문번호 | 상품명 | 옵션 | 수량 | 수령인 | 주소 | 주문일시 |
|---------|-------|------|------|-------|------|---------|

**액션 버튼**

- `엑셀 다운로드` - 발주 대기 건 엑셀 추출
- `발주 완료 처리` - 선택 건 상태 변경
- `발주 이력 보기` - 과거 발주 기록

## 5. 엑셀 추출 형식

### 5.1 기본 컬럼

| 컬럼명 | 설명 | 필수 |
|-------|------|------|
| 주문번호 | 쇼핑몰 주문번호 | O |
| 상품명 | 도매처 원본 상품명 | O |
| 옵션 | 선택 옵션 정보 | O |
| 수량 | 주문 수량 | O |
| 수령인 | 받는 분 성함 | O |
| 연락처 | 받는 분 전화번호 | O |
| 우편번호 | 배송지 우편번호 | O |
| 주소 | 기본 주소 | O |
| 상세주소 | 상세 주소 | △ |
| 배송메모 | 배송 요청사항 | △ |

### 5.2 참고 컬럼 (선택)

| 컬럼명 | 설명 |
|-------|------|
| 도매원가 | 상품 원가 (정산 참고) |
| 주문일시 | 고객 주문 시점 |
| 결제일시 | 결제 완료 시점 |

## 6. 예외 처리

### 6.1 주문 취소 시

| 시점 | 처리 |
|------|------|
| 발주 전 취소 | 발주 목록에서 자동 제외 |
| 발주 후 취소 | 도매처에 취소 요청 필요 (수동) |

### 6.2 부분 취소/변경

- **수량 변경**: 발주 전이면 목록 자동 반영
- **옵션 변경**: 발주 전이면 목록 자동 반영
- **발주 후 변경**: 도매처 협의 필요

### 6.3 발주 제외 대상

- 취소된 주문
- 환불 진행 중인 주문
- 미결제 상태 주문

## 7. 필요 데이터 구조

### 7.1 OrderItem 필드 추가

```prisma
model OrderItem {
  // 기존 필드...

  wholesaleBandId      Int?                  @map("wholesale_band_id")
  wholesaleOrderStatus WholesaleOrderStatus  @default(PENDING)
  orderedAt            DateTime?             @map("ordered_at")

  wholesaleBand        WholesaleBand?        @relation(fields: [wholesaleBandId], references: [id])
}

enum WholesaleOrderStatus {
  PENDING    // 발주대기
  ORDERED    // 발주완료
  SHIPPING   // 배송중
  COMPLETED  // 완료
}
```

### 7.2 발주 이력 테이블 (선택)

```prisma
model WholesaleOrderBatch {
  id              Int       @id @default(autoincrement())
  wholesaleBandId Int       @map("wholesale_band_id")
  orderedAt       DateTime  @default(now()) @map("ordered_at")
  itemCount       Int       @map("item_count")
  totalAmount     Decimal   @map("total_amount") @db.Decimal(12, 2)
  exportedFile    String?   @map("exported_file")
  note            String?   @db.Text

  wholesaleBand   WholesaleBand @relation(fields: [wholesaleBandId], references: [id])
  items           WholesaleOrderBatchItem[]

  @@map("wholesale_order_batch")
}

model WholesaleOrderBatchItem {
  id          Int       @id @default(autoincrement())
  batchId     Int       @map("batch_id")
  orderItemId Int       @map("order_item_id")

  batch       WholesaleOrderBatch @relation(fields: [batchId], references: [id])
  orderItem   OrderItem           @relation(fields: [orderItemId], references: [id])

  @@map("wholesale_order_batch_item")
}
```

## 9. 추후 확장 가능성

| 단계 | 기능 | 설명 |
|------|------|------|
| 1단계 | 현재 | 엑셀 추출 + 수동 발주 |
| 2단계 | 반자동 | 엑셀 자동 생성 + 이메일/카톡 자동 발송 |
| 3단계 | 자동화 | API 연동 자동 발주 (도매처 시스템 연동) |
